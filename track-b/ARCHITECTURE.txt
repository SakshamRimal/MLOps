Agentic loop control flow (POST /chat/research):
  request --> orchestrator --> researcher loop (1 LLM decision per step)
      search_kb / weather / calculator / get_current_time
          -> full result recorded in EvidenceNotes
          -> older tool messages replaced by one-line digests
      submit_answer -> mode=single: in-context self-check
                     -> mode=multi:  verifier agent (fresh context), <= 2 rounds
      ask_user       -> stop_reason=clarification
      step cap       -> forced synthesis from notes (stop_reason=max_steps)
  citation ids are validated against the chunk ids actually retrieved.

Reliability Features:
  - Retry with exponential backoff and randomized jitter (3 attempts)
  - Sliding window rate limiting (30 req/min per IP)
  - Circuit breaker (trips after 5 failures, 30s recovery window)
  - Automatic fallback provider failover (routes to vLLM/Ollama on error)
  - Structured error responses (429, 500, 502, 503)
  - Thread-safe LRU response caching with TTL (256 items, 300s TTL)
  - Non-blocking async event loop with asyncio.to_thread for vector search
  - Request ID correlation (X-Request-ID) and latency tracking (X-Response-Time)
  - Bounded agent loop: max 6 iterations (hard cap 10), forced final synthesis
  - Citation whitelist validation and tool-result clearing in the agent loop

Deployment Options:
  - docker compose up (standard backend + UI stack)
  - docker compose --profile ollama up (with local Ollama fallback)
  - docker compose --profile vllm up (with local vLLM server)
  - Cloud: Azure Container Apps, AWS ECS Fargate, Google Cloud Run

Evaluation:
  - python3 eval/harness.py --base-url http://localhost:8000 --modes single,multi
  - results: eval/results/results.json, eval/results/report.md
